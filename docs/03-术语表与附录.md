# 第 6 章 名词术语表

> 每个名词给出「是什么」和「有什么用」两句解释，按类别分组。

## 6.1 架构与设计

- **端口与适配器（Ports & Adapters）/ 六边形架构**：一种软件架构模式，核心业务逻辑通过「端口」（接口/协议）与外部依赖（数据库、采集器、网络）隔离。**用处**：让业务层不依赖具体技术实现，可替换数据库或采集器而不改业务代码——本项目 `domain/ports.py` 就是端口，`storage/` 是适配器。
- **Protocol（协议类）**：Python 的 `typing.Protocol`，用于定义结构化接口而不强制继承。**用处**：声明「一个仓库必须有哪些方法」，让静态检查 + 运行时鸭子类型都成立。
- **Repository（仓储）**：封装数据持久化逻辑的类，对上层提供「保存/读取」语义而不暴露 SQL。**用处**：隔离存储细节，业务层只调用 `save_many()` 等语义方法。
- **依赖注入（DI）**：在 `main.py:create_app` 里把具体仓储/采集器实例传入服务，而不是在服务内部 new。**用处**：让同一套业务逻辑可跑在 SQLite/Mongo/内存上（测试用内存）。
- **单 worker**：Uvicorn 只跑一个进程/工作线程。**用处**：因为任务、证据包、调度器状态在进程内存里，多 worker 会导致状态分裂，所以必须 `--workers 1`。

## 6.2 核心哲学

- **「能用代码就别用模型」**：精选等决策用确定性代码，模型只做打分/成文等模糊判断。**用处**：省钱、可复现、可解释、可重放验证。
- **确定性 / 可复现**：同一输入必产生同一输出（ID、指纹、决策都不依赖随机/时间）。**用处**：支持回放验证、增量处理、断点重建。
- **代码拥有的决策（code-owned curation）**：精选与否由 `curation.py` 的纯函数决定，不由模型决定。**用处**：任何一条精选都能被重新计算验证。

## 6.3 采集相关

- **Collector（采集器）**：一个数据源适配器，把外部内容（RSS/API/搜索索引）转成统一的 `ArticleRecord`。**用处**：屏蔽不同源的格式差异。
- **Source（信源）**：采集器的持久化配置 + 运行状态（tier、enable、熔断、租约、next_run_at）。**用处**：让操作员可禁用/调整某个源，且重启后保留。
- **SourceRun（信源运行记录）**：一次采集的结构化诊断（窗口、HTTP 状态、抓取/入库/跳过数、错误码、耗时）。**用处**：计算 7 日成功率、定位单源故障。
- **SourceTier（信源等级 T1/T1.5/T2）**：信源权威度分级。T1=一手官方，T1.5=权威媒体，T2=社区/媒体。**用处**：决定评分里的 authority 权重（1.0/0.85/0.65）和采集频率。
- **SourceKind（信源类型）**：RSS/API/BLOG/MP_ACCOUNT/MP_HOT/SOCIAL。**用处**：区分采集方式。
- **SourceType（来源性质）**：OFFICIAL（官方）/PRIMARY（一手）/SECONDARY（二手）。**用处**：决定证据是否「一手来源已核验」。
- **publisher_group（发布者组）**：把同一发布者的多个源归为一组（如 `official:openai`）。**用处**：热点判断里算「独立发布者数量」。
- **signal_only（仅信号）**：标记该源只做线索发现、不可作证据。**用处**：Bing 公众号索引这类源不能进证据门。
- **evidence_eligible（可作证据）**：标记该源内容可参与证据包构建。**用处**：区分「能核验事实」与「只能发现线索」。
- **熔断（Circuit Breaker）**：一种容错模式，连续失败后「打开」开关，暂时不再调用，避免持续打坏源。**用处**：连败 3 次熔断，防止反复请求必然失败的源。
- **CircuitState（CLOSED/OPEN/HALF_OPEN）**：熔断器三态。CLOSED 正常；OPEN 熔断不调用；HALF_OPEN 半开，允许少量探测。**用处**：OPEN 到期后只允许 half-open 探测，成功才闭合。
- **租约（Lease）**：采集前用 `claim_many` 标记某源「正在被某 task 采集」，过期自动释放。**用处**：防止同一源被并发执行（single-flight）。
- **退避（Backoff）**：失败后延迟重试，延迟随时间指数增长（`schedule_minutes × 2^n`）。**用处**：避免瞬时故障被打爆，也尊重源服务器。
- **Retry-After**：HTTP 响应头，服务器要求客户端多久后再试。**用处**：429 时遵守它，避免被限流。
- **全局断网协调（SourceNetworkCoordinator）**：把「本机断网导致的批量超时」与「单源故障」区分开。**用处**：断网时进入共享冷却，每批只探测 3 个，避免所有源同时反复半开。
- **扩窗（7→30 天）**：某类 7 天内容不足 5 条时，自动对该类扩到 30 天。**用处**：保证分类覆盖，同时报告真实缺口。
- **canonicalize_url / 去重（dedup）**：URL 规范化（去 utm_*/fbclid 等追踪参数）+ 标题归一化去重。**用处**：同一文章的多条链接合并成一条。
- **stable_id**：`prefix + sha256(URL)[:20]`，基于 URL 的稳定唯一 ID。**用处**：跨轮采集生成同一 ID，是增量/去重/决策对齐的基石。

## 6.4 分发相关

- **Pipeline（流水线）**：`ContentPipeline.run()` 的同步处理链：预筛 → 分类摘要 → 评分 → 精选。**用处**：把原始文章变成「已评分 + 已精选」的可分发条目。
- **相关性预筛（is_distribution_eligible）**：判断文章是否属于 AI 行业相关内容。**用处**：对混合源过滤非 AI 内容，避免噪音进池。
- **预筛（pre-screen）**：两段式 AI 过滤，去掉纯营销/PR/重复转载。**用处**：用便宜模型先滤掉大部分噪音，节省后续贵模型调用。
- **分类摘要（classify & summarize）**：LLM 把文章分到五分类 + 生成中文摘要。**用处**：统一分类口径，给读者可读摘要。
- **四维评分**：`authority×0.30 + novelty×0.25 + impact×0.25 + practicality×0.20`。**用处**：量化文章质量，作为精选/排序依据。
- **HeatScore**：一篇文章的评分结果（value + confidence + components）。**用处**：存分数和四维分解，支持可解释推荐理由。
- **HeatConfidence（measured/estimated）**：评分是否来自模型实测还是离线估算。**用处**：让读者知道这条分「可信度」如何。
- **CurationDecision（精选决策）**：一篇文章的完整分发结论（selected/eligible/threshold/reason/strategy_version）。**用处**：预计算后落库，页面只读不重算，也是可复现决策的载体。
- **阈值（threshold）**：精选门槛分（T1=60 等，加分类调整）。**用处**：代码判断「是否达到精选」的确定性界线。
- **分类容量（category cap）**：每类最多精选 N 条（默认 6，论文 3）。**用处**：防止单一分类刷屏。
- **质量调整（quality adjustment）**：标题质量微调分（官方价值词 +1.5，文化/娱乐词 −5 等）。**用处**：在热度分之上做小幅排序修正。
- **增量指纹（ingestion_fingerprint / content_fingerprint）**：文章标题+摘要的 sha256。**用处**：`filter_changed` 用它跳过未变化内容，省模型调用。
- **策略版本（strategy version）**：`distribution-v3.2` 之类的版本号，随精选策略变化而变。**用处**：版本变化故意让缓存失效，触发受控重放。
- **精选（curated / selected）**：达到门槛且在该分类 Top N 的文章。**用处**：区分「普通资讯」和「精选资讯」。

## 6.5 创作相关

- **EvidencePack（证据包）**：一个选题的事实依据容器（facts + source_urls + conflicts + unverified_claims）。**用处**：成稿的事实来源，区分已核实/冲突/待核实。
- **EvidenceFact（事实卡）**：单条事实，带来源、数字、日期、版本号、claim_id。**用处**：正文数字/结论的支撑单元。
- **EvidenceSource / EvidenceConflict**：来源元数据 / 证据冲突。**用处**：记录来源身份；标记同一主体不同数值的冲突。
- **claim_id**：事实卡唯一标识（sha256(claim + source_urls)）。**用处**：outline/section 只能引用 brief 授权的 claim_id，是「证据边界」的落地。
- **verified / conflicting / unverified**：事实三态。**用处**：verified 才能进正式写作，conflicting/unverified 是缺口。
- **publisher_identity（发布者身份）**：发布者归一化标识。**用处**：算「独立来源数量」，≥2 个独立发布者才算事实已核验。
- **ContentOpportunity（内容机会）**：一个选题的创作价值评分（7 维加权 creationScore）。**用处**：决定「值不值得写」。
- **AccountProfile（账号画像）**：版本化的账号策略（栏目、禁用词、字数、文风、来源等级）。**用处**：约束每篇成稿的文风与红线。
- **WritingProfile**：一次写作请求的文风参数。**用处**：把画像转成写作参数传给 provider。
- **ContentBrief（写作简报）**：证据门控的写作计划，章节显式绑定 claim_id。**用处**：成文前的「剧本」，确保正文只用已核实的证据。
- **证据门（evidence gate）**：Brief 通过的门槛（证据包 ready + 有已验证 claim + 引用合法）。**用处**：Brief 未过门不能生成正式研究稿。
- **三阶段成文（outline → section → editor）**：大纲 → 逐节成文 → 总编整合。**用处**：分阶段生成可控，每阶段可审计。
- **DraftDocument / DraftVersion**：草稿正文 / 草稿版本。**用处**：记录完整版本历史，每个版本可追溯 prompt/模型。
- **QualityIssue / check_quality**：质量检查项 / 检查函数。**用处**：区分可编辑草稿与可发布草稿。
- **blocking（阻断项）**：导致不能定稿/导出的确定性质量问题。**用处**：任何确定性阻断项都不能被人工确认绕过。
- **人工确认（human approval）**：作者用固定确认语完成最终事实核对。**用处**：自由编辑后需重新确认，避免静默沿用旧结论。
- **finalize**：独立生成的定稿版本。**用处**：只有人工确认后才生成，可导出。
- **原创性检测（normalized-char-12gram）**：归一化后取连续 12 字符 n-gram，算 Jaccard 重叠 + 最长连续重复段。**用处**：草稿对主灵感原文重叠 >10% 禁止定稿。
- **SimilarityReport**：一次原创性检测结果（score/ngram_overlap/longest_match/passed）。**用处**：可复现的原创度证据。
- **灵感导入（InspirationSource）**：抓取/解析的公开 URL 参考文章。**用处**：提供主题/结构借鉴，事实仍需独立来源。
- **SSRF（服务端请求伪造）**：攻击者诱导服务器请求内网地址。**用处**：`validate_external_url` 拦截本机/内网/保留网段，防止被利用。
- **reusable_blueprint（抽象蓝图）**：从灵感原文提取的开篇方式/节奏/组织等抽象特征。**用处**：只借鉴结构，不抄袭内容。
- **作者材料（AuthorInput）**：作者确认真实经验/观点/案例/数据。**用处**：避免把模型生成内容冒充亲历。
- **PromptVersion / template_hash**：不可变 prompt 契约 / prompt 内容哈希。**用处**：审计每次生成用了哪个版本的 prompt。
- **LlmCallRecord（调用记录）**：单次模型调用（token/耗时/成本/错误码）。**用处**：成本控制 + 生成审计。
- **GenerationAudit（生成审计）**：prompt 契约 + 调用记录 + 内容质量回放。**用处**：可追溯每篇成稿的生成过程。

## 6.6 Agent 相关

- **LangGraph**：基于图的状态机框架，用节点 + 条件边表达 Agent 循环。**用处**：实现 `decide → execute → decide` 循环。
- **StateGraph**：LangGraph 的图构建器。**用处**：定义节点、边和状态结构。
- **decide→execute→decide**：Agent 的循环模式：先决策（调用工具还是回答）→ 执行工具 → 再决策。**用处**：让模型能多轮调用工具直到得到答案。
- **function calling / tool call**：模型返回结构化「调用某函数 + 参数」的能力。**用处**：让模型能调用 `search_ai_news` 等本地工具。
- **Observation**：一次工具执行的结果。**用处**：回填给模型，作为下一轮决策依据。
- **needs_evidence**：research 模式的结束状态，表示「正常完成缺口判断但不能进入正式写作」。**用处**：如实报告证据不足，不冒充完成。

## 6.7 存储相关

- **SQLite / SQLAlchemy Core**：文件型关系数据库 / SQLAlchemy 的底层（非 ORM）API。**用处**：单机持久化；手写 SQL 获得跨库可控性。
- **WAL（Write-Ahead Logging）**：SQLite 预写日志模式。**用处**：读写并发性能更好（从 `.db-wal` 文件可看出已启用）。
- **schema_migrations（迁移表）**：记录已应用的 schema 版本。**用处**：启动时按序执行迁移，保证 schema 一致性。
- **迁移（migration）**：schema 变更脚本（加表/加列/回填）。**用处**：让老库能平滑升级到新 schema 而不丢数据。
- **upsert（on_conflict_do_update）**：插入或冲突时更新。**用处**：`save_many` 幂等写入，重复采集不产生重复行。
- **精选镜像（SelectedSync）**：把精选集导出成可增量同步的镜像。**用处**：供 AIHOT 等下游客户端全量+增量拉取。
- **双游标（snapshot + changes）**：先全量快照，再增量变更。**用处**：客户端首次全量、之后增量，幂等同步。
- **SnapshotRequiredError**：游标过期需重取快照的提示。**用处**：变更保留超限时，强制客户端重建镜像。
- **ETag**：HTTP 响应内容哈希，配合 If-None-Match。**用处**：304 缓存命中，减少不必要传输。
- **keyset 分页**：用「上一页最后一条的排序键」定位下一页，而非 offset。**用处**：翻页期间插入新文章不会挤动已开始的结果集。
- **cursor（游标）**：分页状态编码（anchor + sort_at + id + signature）。**用处**：绑定查询条件/排序/策略版本，保证翻页稳定。
- **TTL（Time To Live）**：数据过期时间。**用处**：快照会话 900 秒过期，防无限占用。

## 6.8 API / 观测相关

- **FastAPI**：Python 异步 Web 框架。**用处**：声明式路由 + 自动 OpenAPI 文档。
- **Problem JSON（RFC 7807）**：标准化的错误响应格式。**用处**：公开 v1 错误统一用 `application/problem+json`，含 code/requestId/retryable。
- **requestId**：请求唯一标识（`req_` + uuid）。**用处**：日志/诊断里定位单次请求。
- **retryable**：错误是否可重试的标记。**用处**：客户端据此决定是否重试。
- **Server-Timing**：响应头，报告服务端耗时。**用处**：性能观测。
- **缓存状态（HIT/MISS/BYPASS）**：响应是否命中缓存。**用处**：`X-Cache-Status` 头 + 观测聚合。
- **openapi-v1.json（公开契约）**：裁剪出的公开只读 API 文档。**用处**：对外声明稳定的机器接口，只含 8 个分发端点。
- **RSS feed**：把精选/日报输出成 RSS 2.0。**用处**：订阅客户端（RSS 阅读器）消费。
- **observability（观测）**：进程内 HTTP 观测（请求数/错误/缓存命中率/p50/p95）。**用处**：`/api/ops/http-observability` 提供本地诊断。

## 6.9 Story / 评估相关

- **Story 影子引擎（shadow）**：零 token 的确定性「旁路投影」，对同一批数据跑聚类验证，只读不改。**用处**：验证 Story 聚类策略而不污染正式分发。
- **聚类（clustering）**：把描述同一事件的多个报道归成一个 Story。**用处**：热点判断（多源报道同一事件才算热点）。
- **并查集（union-find）**：高效合并集合的数据结构。**用处**：按 SAME 边合并文章成簇，路径压缩加速。
- **硬否决（hard veto）**：8 条不可逾越的否定规则（如「不同版本」「预测 vs 发生」）。**用处**：保证聚类不被传递边错误桥接。
- **st_ 标识**：Story 的稳定公开标识（`st_` + 32 位 hex）。**用处**：对外暴露稳定 ID，内部 id 会变。
- **合并/拆分谱系**：Story 合并（merged_into_id）和拆分的版本留痕。**用处**：追溯一个 Story 的演化历史。
- **金标（gold）**：纯人工标注的样本集（`annotation_method=="human"`）。**用处**：回放与发布门的地面真值。
- **回放（replay）**：用确定性策略对金标重放打分，量化策略与人工一致性。**用处**：发布门里金标这一关的通过证据。
- **发布门（release-gate）**：上线硬闸门，聚合源可靠性 + 金标回放。**用处**：缺一即 blocked，不能放行上线。
- **双人盲审**：两个独立评审人盲标同一批样本。**用处**：降低单人标注偏差。
- **冲突裁决（adjudication）**：两人结果不一致时由第三人仲裁。**用处**：解决评审分歧，产出最终金标。
