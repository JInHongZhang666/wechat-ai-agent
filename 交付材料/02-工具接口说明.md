# AI 信息小屋 Agent 工具接口说明

## 1 接口约定

Agent 使用 OpenAI 兼容的原生 function calling。工具定义由 Pydantic 模型生成 JSON Schema，参数采用严格模式：不接受额外字段，不接受将字符串自动转换成数字，也不接受未声明的枚举值。

所有工具统一返回以下外层结构：

```json
{
  "ok": true,
  "tool": "search_ai_news",
  "data": {},
  "error_code": null
}
```

失败时返回 `ok=false`、稳定的 `error_code` 和 `retryable`，底层异常文本不会直接暴露，避免本地路径、密钥或服务商细节泄漏。

## 2 search_ai_news

用途：查询本地已经采集并通过分发资格判断的 AI 资讯。它不是实时全网搜索。

输入 Schema：

```json
{
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "query": {"type": "string", "maxLength": 200, "default": ""},
    "window": {"enum": ["24h", "7d", "30d"], "default": "7d"},
    "limit": {"type": "integer", "minimum": 1, "maximum": 10, "default": 5}
  }
}
```

调用示例：

```json
{"query": "OpenAI", "window": "7d", "limit": 5}
```

成功结果中的 `data` 包含 `scope`、`window`、`query`、`matched_count` 和 `items`。每条资讯包含文章 ID、标题、摘要、原始链接、发布时间、来源名称、来源类型、来源类型是否已验证和来源身份。

## 3 find_supporting_sources

用途：针对本轮已经观察到的文章，继续从本地合格资讯池中查找同一事件的独立补充来源。

输入 Schema：

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["article_id", "query"],
  "properties": {
    "article_id": {"type": "string"},
    "query": {"type": "string", "minLength": 2, "maxLength": 200},
    "window": {"enum": ["24h", "7d", "30d"], "default": "7d"},
    "limit": {"type": "integer", "minimum": 1, "maximum": 10, "default": 5}
  }
}
```

调用示例：

```json
{"article_id": "article-123", "query": "OpenAI GPT API", "window": "30d", "limit": 5}
```

如果 `article_id` 未在本轮搜索结果中出现，返回 `ARTICLE_NOT_OBSERVED`。该限制阻止模型把臆造 ID 传入证据链。

## 4 build_research_evidence

用途：用本轮已观察到的同一事件文章 ID 构建证据包，并检测独立来源、一手来源、待核实内容和事实冲突。

输入 Schema：

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["article_ids"],
  "properties": {
    "article_ids": {
      "type": "array",
      "minItems": 1,
      "maxItems": 5,
      "items": {"type": "string"}
    }
  }
}
```

调用示例：

```json
{"article_ids": ["article-123", "article-456"]}
```

关键输出字段：

- `facts`：从已采集摘要中抽取并能绑定来源的事实。
- `independent_source_count`：按 `source_identity` 去重后的独立来源数。
- `gaps`：证据缺口列表。
- `evidence_ready`：是否达到 Research 模式的输出门槛。
- `conflicts`：同一事实的冲突描述。
- `limitation`：明确说明摘要匹配不等于全文核验，不能自动发布。

## 5 refresh_news_sources

用途：刷新系统中已经配置且到期的信源。此工具没有输入参数，但只有 API 请求显式传入 `refresh_sources=true` 时才能执行。

输入 Schema：

```json
{"type": "object", "additionalProperties": false, "properties": {}}
```

未授权调用返回 `REFRESH_NOT_ALLOWED`。一次 Agent 运行中重复调用会复用第一次结果，避免重复触发带副作用的采集任务。

## 6 search_aihot_news

用途：查询 AIHOT 最近 24 小时或 7 天的公开 AI 资讯，用于扩大近期资讯发现范围。该工具是独立扩展，不属于本地证据库。

输入 Schema：

```json
{
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "query": {"type": "string", "maxLength": 200, "default": ""},
    "window": {"enum": ["24h", "7d"], "default": "7d"},
    "category": {"enum": ["ai-models", "ai-products", "industry", "paper", "tip", "opinion", null]},
    "mode": {"enum": ["selected", "all"], "default": "selected"},
    "limit": {"type": "integer", "minimum": 1, "maximum": 10, "default": 8}
  }
}
```

调用示例：

```json
{"query": "Claude", "window": "24h", "category": "ai-models", "mode": "all", "limit": 8}
```

返回结果同时给出原始来源链接和 AIHOT 页面链接，并标注 `provenance=external_aggregator`。AIHOT 的条目 ID 以 `aihot:` 为前缀，不能传给本地 `build_research_evidence`。

## 7 主要错误码

| 错误码 | 含义 | 是否建议重试 |
|---|---|---|
| `INVALID_TOOL_JSON` | 模型生成的 JSON 无法解析 | 是，修正参数后重试 |
| `INVALID_TOOL_ARGUMENTS` | 参数不符合 JSON Schema | 是，修正参数后重试 |
| `UNKNOWN_TOOL` | 工具未注册或越权调用 | 否 |
| `ARTICLE_NOT_OBSERVED` | 文章 ID 未在本轮查询中出现 | 是，先搜索再构建证据 |
| `REFRESH_NOT_ALLOWED` | 用户没有授权刷新信源 | 否 |
| `REFRESH_UNAVAILABLE` | 当前服务没有可用采集器 | 否 |
| `TOOL_EXECUTION_FAILED` | 存储或服务执行失败，细节已脱敏 | 否 |
| `AIHOT_UPSTREAM_UNAVAILABLE` | AIHOT 限频或服务端暂时不可用 | 是 |
| `AIHOT_REQUEST_REJECTED` | AIHOT 拒绝请求 | 否 |
| `AIHOT_INVALID_RESPONSE` | AIHOT 响应不完整或格式异常 | 是 |
